## tcp_node — готовый узел для Unix-хостов

`tcp_node` (`src/bin/tcp_node.rs`) — исполняемый yggdrasil-lite-узел для
**Termux, Linux и OpenWrt**. Подключается к публичным TCP-пирам, работает как
leaf-узел, сам замеряет задержку до кандидатов и меняет медленных пиров, отдаёт
статус через HTTP и пробрасывает TCP и UDP порты по Yggdrasil. Зависит только от
`rand` и `heapless` — без TLS и C-библиотек, компактный статический бинарник.

### Флаги

| Флаг | Описание |
|------|----------|
| `--key FILE` | Файл ключа (64 hex). Создаётся при первом запуске с правами 600; определяет адрес узла — держите в секрете |
| `--peers FILE` | JSON-список публичных пиров (`publicnodes.json`) |
| `--target N` | Число исходящих слотов (1..32, по умолчанию 3) |
| `--allow KEY` | Разрешённый публичный ключ (повторяемый). Датаграммы от прочих ключей отбрасываются |
| `--api ADDR` | HTTP-статус-сервер (дашборд + JSON). Слушает только loopback |
| `--html FILE` | Своя HTML-разметка страницы узла |
| `--forward PORTS` | Проброс TCP-портов (до 16) |
| `--forward-udp PORTS` | Проброс UDP-портов (до 16) |
| `--listen PORT` | Принимать входящие TCP-пиры (до 16 сверх `--target`); порт анонсируется в LAN-маячках |
| `--lan` | Поиск пиров в локальной сети по multicast-маячкам |
| `--quality-interval SECS` | Интервал проверки сети (по умолчанию 300, минимум 10) |
| `--ping IPV6` | Замер RTT до узла |
| `--send IPV6 MSG` | Разовая отправка датаграммы |
| `--send-udp IPV6 PORT MSG` | Тестовая UDP-датаграмма каждые 5 с |

### Базовый запуск (Termux)

```sh
pkg install rust git curl
bash scripts/termux.sh build     # собирает tcp_node
bash scripts/termux.sh peers     # скачивает список публичных пиров в ~/peers.json
bash scripts/termux.sh run       # запускает узел с дашбордом на 127.0.0.1:8080
bash scripts/termux.sh run --lan --listen 40001   # доп. флаги передаются как есть
```

Вручную то же самое:

```sh
git clone https://github.com/vasil646srb/yggdrasil-lite && cd yggdrasil-lite
cargo build --release --bin tcp_node

curl -fsSL -o ~/peers.json https://publicpeers.neilalexander.dev/publicnodes.json
./target/release/tcp_node --key ~/ygg.key --peers ~/peers.json \
    --target 3 --api 127.0.0.1:8080
```

Дашборд: `http://127.0.0.1:8080/` · статистика: `curl http://127.0.0.1:8080/api/stats`.
API слушает только 127.0.0.1 и не имеет аутентификации — не выносите на 0.0.0.0.

Файл ключа создаётся с правами `600`; если он оказался читаем другими
пользователями, узел печатает предупреждение. Держать узел живым с погасшим
экраном: `termux-wake-lock` и отключите оптимизацию батареи для Termux.

### Локальная сеть и входящие пиры

`--lan` включает поиск соседей в локальной сети: узел рассылает маячки (магия
`YGGL`) в группу `239.255.42.7:9001` раз в 3 с и добавляет найденные узлы как
кандидатов. `--listen PORT` открывает приём входящих TCP-пиров и анонсирует этот
порт в маячках — так два узла в одной сети находят друг друга без публичных
пиров. Сверх `--target` принимается не более 16 входящих соединений.

### Автоподбор пиров и замена медленных

Узел выбирает пиров в две стадии, чтобы не тратить слоты на недоступные адреса:

1. **Проба до дозвона.** Все кандидаты из `--peers` (и найденные по `--lan`)
   проверяются обычным TCP-connect, параллельно в 8 потоков, таймаут 2 с на адрес.
   Результат идёт в скользящее среднее (`record_probe`), недоступный кандидат
   получает штраф 5000 мс и уезжает в конец очереди. Пока идёт первый раунд,
   дозвон удерживается (`set_dial_enabled(false)`), но не дольше 60 с. Повторный
   раунд — каждые 600 с.
2. **Замена по качеству.** Раз в `--quality-interval` (и каждые 30 с, пока корень
   медленный) узел замеряет RTT эхо-запросами: до каждого подключённого пира и
   до глобального корня каждые 10 с, до адресов клиентов из `--allow` — каждые 10 с.
   Если RTT до корня > **200 мс** или до разрешённого клиента > **150 мс**, самый
   медленный исходящий пир отключается (не чаще раза в 30 с) и заменяется на
   лучшего кандидата; отключённый пир не перезванивается 15 минут.

### Страница узла на порту 80 и API

Узел отвечает на ICMPv6 echo от разрешённых ключей и отдаёт статусную страницу
на оверлейном TCP-порту 80 (если порт 80 не занят пробросом). Открыть её можно с
узла, чей ключ есть в `--allow`, через SOCKS-прокси yggstack:

```sh
curl -x socks5h://127.0.0.1:1080 http://[<device-address>]/
```

Страница обновляется каждую секунду и показывает:

- по каждому слоту `--target`: адрес пира, RTT, статус корня («главный корень» /
  «чужой корень» / «ожидание»), время соединения;
- сводку по корню: измеренный RTT и список ключей, сгруппированных по корню;
- таблицу разрешённых клиентов (`--allow`) с их адресами и RTT;
- лог последних замен пиров и кнопку **теста скорости**.

Тест скорости запрашивает `GET /speed` — узел отдаёт 256 КБ нулей
(`Content-Type: application/octet-stream`), страница считает Мбит/с и выводит
объём и длительность. Полезна как быстрая проверка пропускной способности
проброса.

## Проброс TCP-портов (SSH к роутеру или телефону)

`tcp_node --forward` делает TCP-порты этого хоста доступными по Yggdrasil.
Порты указываются на старте. Подключиться могут только ключи из `--allow`, и
открыты только перечисленные порты.

### Формат `--forward`

`--forward` принимает разделённый запятыми список портов (до 16), флаг можно
повторять. Поддерживаются два формата элемента:

- `PORT` — оверлейный порт совпадает с локальным. Пример: `--forward 22`
  открывает порт 22 в оверлее и маппит его на 127.0.0.1:22;
- `OVERLAY:LOCAL` — явный маппинг: оверлейный порт `OVERLAY` ведёт на
  локальный порт `LOCAL`. Пример: `--forward 2222:22` открывает оверлейный
  порт 2222 → 127.0.0.1:22.

Оба формата можно смешивать в одном списке:

```sh
tcp_node --key ~/ygg.key --peers ~/peers.json \
    --allow <client-public-key> --forward 22,8080,9000:9001
```

Что это открывает:

- `22` — оверлейный 22 → 127.0.0.1:22 (совпадающий номер);
- `8080` — оверлейный 8080 → 127.0.0.1:8080 (совпадающий номер);
- `9000:9001` — оверлейный 9000 → 127.0.0.1:9001 (явный маппинг).

Локальное соединение, которое не удалось открыть (таймаут 2 с), сбрасывается в
сторону клиента. Клиент должен запускать полный стек Yggdrasil (yggdrasil-ng с
TUN или yggstack с SOCKS-прокси) и использовать разрешённый ключ. С SOCKS-прокси
yggstack на 127.0.0.1:1080:

```sh
ssh -o ProxyCommand="nc -X 5 -x 127.0.0.1:1080 %h %p" -p 22 root@<device-address>
```

### Ограничения встроенного TCP

Для интерактивных сессий (SSH), не для больших передач: одно соединение на
клиентский порт, без congestion control и TIME_WAIT; при пробросе порта 80
статусная страница узла отключается.

## Проброс UDP-портов (`--forward-udp`)

`--forward-udp` работает по тем же правилам, что и `--forward`: тот же формат
`PORT[:LOCAL]`, тот же список до 16 портов, те же ограничения по ключам из
`--allow`. Отличие — транспорт: узел принимает UDP-датаграммы от разрешённых
клиентов (IPv6 + UDP, контрольная сумма обязательна и проверяется) и пересылает
их в локальный сервис на 127.0.0.1, а ответы возвращает по оверлею.

```sh
# оверлейный UDP 5353 → локальный 53, оверлейный 51820 → локальный 51820
tcp_node --key ~/ygg.key --peers ~/peers.json \
    --allow <client-public-key> --forward-udp 5353:53,51820
```

Сессии ведутся по тройке (ключ клиента, порт клиента, оверлейный порт):

- до **64** одновременных сессий;
- сессия удаляется после **60 с** без трафика;
- максимальный payload одной датаграммы — **1232 байта** (минимальный MTU IPv6
  1280 минус заголовки IPv6 и UDP); более крупные датаграммы отбрасываются;
- новый клиент сверх лимита сессий не обслуживается, пока не освободится слот.

Для проверки канала есть `--send-udp IPV6 PORT MSG`: узел отправляет эту
датаграмму на адрес оверлея каждые 5 с и печатает ответы.

## Проверка сети

```sh
tcp_node --key ~/ygg.key --peers ~/peers.json --ping <ipv6>            # RTT
tcp_node --key ~/ygg.key --peers ~/peers.json --send <ipv6> hello      # датаграмма
tcp_node --key ~/ygg.key --peers ~/peers.json \
    --send-udp <ipv6> 5353 hello                                       # UDP каждые 5 с
```

## Сборка для роутера (OpenWrt)

Собирайте под CPU роутера, лучше мусл-статик: бинарнику не нужен libc на
устройстве. Целевой триплет смотрите через `uname -m` на роутере.

```sh
# пример: aarch64-роутер (уточните для своего устройства)
rustup target add aarch64-unknown-linux-musl
cargo build --release --bin tcp_node --target aarch64-unknown-linux-musl
scp target/aarch64-unknown-linux-musl/release/tcp_node root@192.168.1.1:/usr/bin/
```

`scripts/build.sh` делает то же самое, подбирая тулчейн OpenWrt
(`OPENWRT_TOOLCHAIN_BIN`). `tcp_node` зависит только от `rand` и `heapless`
(ни TLS, ни C-библиотек), поэтому кросс-сборке не нужны дополнительные системные
библиотеки, а релизные сборки стрипаются. Установка сервиса —
`openwrt/tcp_node.init` (см. комментарии в файле).
